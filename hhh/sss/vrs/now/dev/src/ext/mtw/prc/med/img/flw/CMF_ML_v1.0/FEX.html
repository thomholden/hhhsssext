Fast Continuous Max-Flow Algorithm to 2D/3D Multi-Region Image Segmentation

by Jing Yuan

 

15 Dec 2011 (Updated 16 Dec 2011)

Description

This software implements the fast continuous max-flow algorithm to 2D/3D multi-region image segmentation (Potts model). It provides three implementations: matlab, C and GPU (cuda based). All the source files are provided. So it is easy for you to incorporate the algorithms in your own applications.

2D/3D multi-region image segmentation can be modeled as computing the multi-way cuts, i.e. Potts model, in the spatially continuous setting, and solved by its convex relaxation. The continuous max-flow formulation is dual/equivalent to such convex relaxed Potts model problem. On the other hand, it also leads to a new fast algorithm in numerics, i.e. the fast continuous max-flow algorithm. More details are given in the document CMFML_README.pdf. Wish this software would be helpful for you and your works!

For image segmentation with two regions: foreground and background, the fast continuous max-flow algorithm can be downloaded through:
http://www.mathworks.com/matlabcentral/fileexchange/34126
which is simpler.

Email Jing Yuan (cn.yuanjing@gmail.com) for the questions, comments and suggests. You are welcome to propose your ideas of improvements. Any contribution will be kindly acknowledged in CMFML_README.pdf.
MATLAB release MATLAB 7.10 (R2010a)
Other requirements any C compiler, CUDA C compiler

If you need to segment the 3D volume into two regions, the other package fits you more. Its link is:
http://www.mathworks.com/matlabcentral/fileexchange/34126

If your task is a multi-region segmentation (n>= 3), this package works for you.

This package implements the current continuous max-flow algorithm for multi-region segmentation. There are three implementation: matlab, C-mex (running on CPU), cuda-mex (running on GPU). The matlab code, which is CMF3D_ML_cut.m, is the slowest but easy to validate your idea. The cuda-mex is the fastest and fits the real application. So I suggest you first modify the matlab code CMF3D_ML_cut.m to check the potential idea and parameters. Then you can modify the test_CMF3D_ML.m as you tested. test_CMF3D_ML.m is basically a matlab wrapper to use c-mex and cuda-mex codes. Please email me if you still have questions.

02 Jan 2012 Jing Yuan

To Maya:

The segmentation model, i.e. Potts model, deals with two types of cost functions: data costs and length costs. The data cost functions: d_i(x) gives the cost to label the pixel x as the segmentation area i; while the length cost evaluates the total length of each segmentation area. In this way, Potts model computes the segmentation areas with the minimum total costs of both data and lengths.

The data costs d_i(x), as your inputs, come from your image model. The simplest way is to apply the Gaussian model, which amounts to:
d_i(x) = (f(x) - l_i)^2
where f(x) is your image data and l_i is the mean gray-value of the segmentation area i.

Of cause, another image model, like histogram-based, can also be applied. Please be free to email me, when you have any other question about using this software.

To Med:

There are another ones who asked the same question. Hope the following part answer you:

Concerning this question, for the 3D case, the output u is a 4D variable which represents n 3D labeling functions, i.e. u(x,y,z,1), ..., u(x,y,z,n). As the convex relaxation theory, each u(x,y,z,i) takes the value in [0,1] and, at each point (x,y,z), the segment region is indicated by k where u(x,y,z,k) is the maximum of u(x,y,z,i), i=1...n.

So the final label function I(x,y,z) at each point (x,y,z) is given by

[um,I] = max(u, [], 4);

You can check this with the last lines of CMF3D_ML_Cut.m. Then you can draw the surfaces indicated by I(x,y,z).

Or, you can also approximate the surfaces directly by u(x,y,z,i), i=1...n. For example, you can draw the first surface approximately by isosurface(u(x,y,z,1), 0.5). Of cause, it is mostly smaller than the real one.

For more details, you can also read my paper at ECCV'2010.

FAQ 1: How to make GPU work properly?

The constant BLOCK_SIZE determines the total number of threads when the kernel is launched. For the 2D case, it is 16; so 16^2 = 256 threads are launched. For the 3D case, it is 8; so 8^3 = 512 threads are launched.

Please check the specification of your GPU and choose a proper value for BLOCK_SIZE.

FAQ 2: How to load the 3D data?

The 3D data file *.nii is written in the format of nifti. You can open it by the function load_nii(), which can be downloaded by the matlab toolbox: http://www.mathworks.com/matlabcentral/fileexchange/8797 .
